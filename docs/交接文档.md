## 5. 如何使用（现场 / 开发）

### 5.1 安装现成 APK（现场最快）

1. 打开 [Releases](https://github.com/ciahua/cywms/releases)，下载最新 **`cywms-pda-debug.apk`**（当前 Latest：`pda-v1.1.1`）
2. PDA 上允许未知来源 / 安装未知应用
3. `adb install -r cywms-pda-debug.apk` 或文件管理器安装
4. 打开 App → 展开「服务器与代理设置」：
   - **现场内网**：清空代理，主机 `172.16.5.7`，端口 `8080`
   - **远程**：填当前有效的 ngrok URL（默认常量可能已过期，务必现场改）
5. 「测试连接」通过后，用 Jeecg 账号登录（联调常用示例：`admin` / `e`，以现场账号为准）

登录成功后会静默检查 GitHub 更新；有新版本可确认后下载安装（需允许本应用安装未知应用）。

### 5.2 Android Studio 开发运行

1. 打开工程目录 **`android-pda/`**（不是仓库根目录）
2. Sync Gradle，选模拟器或真机 Run
3. 命令行：

```bash
cd android-pda
./gradlew :app:assembleDebug
# 产物：app/build/outputs/apk/debug/app-debug.apk
```

### 5.3 生产领料操作路径

首页 → **领料作业 / 生产领料** → 选单 → 选明细行 → 扫码（枪扫或模拟）→ 提交。

扫码约定：

| 项 | 值 |
|----|-----|
| Intent Action | `com.service.scanner.data` |
| Extra | `ScanCode` |
| 条码格式 | 常含 `*` 分段（如 `物料代码*数量*...`） |

模拟器无扫枪时，可用键盘楔形输入整段条码后回车，或 `adb shell am broadcast` 发上述广播做联调。

## 6. 发版流程（维护必读）

版本规则：**从 `v1.0.0` 起，每次发版末位 +1**（`v1.0.1`… 进位到 `v1.1.0` 等按需）；`versionCode` 同步递增（当前 `10101` ↔ `v1.1.1`）。

1. 改 `android-pda/app/build.gradle.kts`：
   - `versionName`（如 `"v1.1.2"`）
   - `versionCode`（如 `10102`）
2. 构建：

```bash
cd android-pda
./gradlew :app:assembleDebug
cp app/build/outputs/apk/debug/app-debug.apk cywms-pda-debug.apk
```

3. 创建 GitHub Release：
   - Tag：**`pda-{versionName}`**（例：`pda-v1.1.2`）
   - 附件文件名必须为：**`cywms-pda-debug.apk`**
4. 客户端通过 `https://api.github.com/repos/ciahua/cywms/releases` 拉列表，按 semver 取最高版本；现场若 GitHub 慢，需考虑镜像或内网分发（历史上外网拉取曾失败）。

**注意：** 不要把体积很大的旧 Flutter APK 提交进 Git；对照包放本地或 Release 即可。

## 7. 源码地图（从哪改）

根包：`com.chenyang.cywms`

| 目录 / 文件 | 职责 |
|-------------|------|
| `MainActivity.kt` / `WmsApp.kt` / `AppContainer.kt` | 入口、依赖组装 |
| `nav/WmsNavHost.kt` | 路由；**新模块在此挂导航**，首页 `onModuleClick` 接线 |
| `ui/login/` | 登录、更新检查 UI |
| `ui/home/` | 首页分组（`HomeModules.kt` 定义 14 入口） |
| `ui/produce/` | **生产领料** 三屏 + ViewModel（其它业务可照此复制） |
| `ui/common/` | PDA 脚手架、扫码捕获、软键盘策略 |
| `data/api/ApiClient.kt` | 动态 BaseUrl、Token、ngrok Header |
| `data/api/ProduceIssueApi.kt` | 生产领料 Retrofit 接口 |
| `data/api/UpdateRepository.kt` | GitHub 更新检查与下载 |
| `data/prefs/SessionPrefs.kt` | 连接信息与会话；`DEFAULT_PROXY_URL` 默认代理 |
| `scanner/` | 广播扫码、ScanBus、键盘楔形 |
| `res/xml/network_security_config.xml` | 允许内网 cleartext HTTP |

扩展新模块推荐顺序：契约清单找路径 → 建 `*Api` / Repository / Model → 三屏 Compose → `HomeModules` 已有 id → `WmsNavHost` 接线。

## 8. 后端与文档索引

| 文档 | 用途 |
|------|------|
| `legacy/辰阳电子WMS_PDA_Android重建开发说明书.md` | **权威**：旧 APK 行为、模块、接口、联调 |
| `docs/pda-rebuild/重建开发方案.md` | 技术选型、UI 规范、分期、风险 |
| `docs/pda-rebuild/模块功能矩阵.md` | 旧 14 模块 ↔ 新 Screen / 优先级 |
| `docs/pda-rebuild/接口契约清单.md` | Method/Path；**拼写错误 URL 必须原样**（如 `stcoktaking`、`outsoucetuiliao`） |

兼容原则：

- **不改**现网 Controller / Shiro / 生产库结构（除非单独发版回归）
- Body 字段名与大小写与旧 APK 一致（如 `barcodelist`、`scanqtyList`）
- 成功判据：`success == true`
- 鉴权：`X-Access-Token`；ngrok 时加 `ngrok-skip-browser-warning: true`

后端业务多在 `jeecg-module-demo`；仓库内**没有**后端源码，建议另存只读对照（勿提交密钥）。

## 9. 已知问题与风险

| 问题 | 说明 / 建议 |
|------|-------------|
| PR 未合并 | 日常开发继续基于 `cursor/pda-rebuild-plan-695c`，合并前先与负责人确认 |
| 默认 ngrok 过期 | `SessionPrefs.DEFAULT_PROXY_URL` 可能失效；现场改登录页代理即可 |
| 多数模块仅入口 | 勿当作全功能上线；优先按矩阵 P0：委外领料、盘点、移库等 |
| 条码「不匹配」 | v1.1.1 对 `verify` / 余量 0 / 台账双记录做了客户端缓解；根因可能在后端数据，需对照 Web 台账 |
| 扫码双通路 | 广播 + 键盘楔形需去重（已有修复，改扫码逻辑时回归） |
| GitHub 更新依赖外网 | 厂区无外网时要改分发渠道或预装 APK |
| 无旧签名 | 新包名并行安装，不会覆盖旧 Flutter 包 |
