# 江苏辰阳电子 WMS · PDA Android 重建开发方案

> 目标：在**不使用 Flutter** 的前提下，用原生 Android 重建 PDA 端；**功能模块与后端接口与旧 APK 兼容**；**UI 全面重设计**，达到工业仓储软件的专业观感。  
> 依据材料：`app-debug_1763393133238.apk` +《辰阳电子WMS_PDA_Android重建开发说明书.md》（需纳入本仓库 `legacy/`）。

---

## 1. 结论摘要

| 维度 | 决策 |
|------|------|
| 技术栈 | **Kotlin + Jetpack Compose + Material 3**，单 Activity 多 Screen |
| 架构 | Clean Architecture：`ui` / `domain` / `data`，MVVM + UseCase |
| 兼容策略 | **协议层 1:1 复刻旧接口**（路径、Method、Header、Body、字段名），UI 与导航可自由重做 |
| 网络 | 登录页可配置 **Base URL（IP:端口）** 与 **代理地址**（含 ngrok），本地持久化 |
| 扫码 | 优先系统/厂商扫描枪键盘楔入；辅以 CameraX + ML Kit |
| 最低系统 | API 26（Android 8.0），目标 API 34+ |

旧 APK 源码丢失不可恢复时，以「逆向说明书 + 抓包/反编译校验」作为唯一真相源；本方案把兼容边界钉死在 **HTTP 契约**，而不是旧布局或旧 Activity 名。

## 3. 技术选型说明（为何不用 Flutter）

| 选型 | 理由 |
|------|------|
| Jetpack Compose | 毛玻璃、深色遮罩、动效、自适应 PDA 分辨率实现成本低 |
| OkHttp + Retrofit + kotlinx.serialization / Moshi | 易做「动态 BaseUrl + 代理」；拦截器统一挂 Token |
| DataStore | 持久化账号、服务器、代理、上次仓库等 |
| Navigation Compose | 主界面分类 → 业务流一屏一职责 |
| Hilt | 依赖注入，便于切换 Mock / 真机 / ngrok 环境 |
| CameraX + ML Kit（可选） | 无激光枪时的软扫兜底 |

不引入 Flutter/RN：避免双引擎、体积与扫码枪键盘楔入兼容性风险；PDA 工业场景更适合原生。

## 4. 兼容边界（必须做 vs 可重做）

### 4.1 必须兼容（与旧 APK 行为对齐）

- 全部业务模块能力（以说明书模块列表为准，典型含：登录鉴权、入库、出库、拣货、盘点、移库/调拨、库存查询、条码绑定、单据确认等）
- 请求 URL 路径、HTTP Method、Query/Form/JSON 字段名与类型
- 鉴权方式与会话续期 / 401 处理
- 扫码输入约定（回车结束、前缀剥离、长度校验）
- 业务状态机（单据状态流转、可操作时机、错误码提示文案可优化但码值不变）

### 4.2 允许重做

- 视觉风格、布局、图标、字体、动效
- 信息架构：主页分组、入口命名、操作步骤引导
- 本地校验提示的表述（不改变提交逻辑）
- 离线缓存策略（若旧版无离线，新版可先不做）

### 4.3 兼容验证方式

- 同一后端（含 ngrok）下，旧 APK 与新 App **对同一单据**走通一遍，对比请求 Diff
- 契约测试：`MockWebServer` 回放说明书中的成功/失败样例
- 字段级断言：序列化 DTO 与说明书 JSON 样例一致

## 5. 功能模块与信息架构（UI 重设计）

> 下列分组为**建议信息架构**；最终以说明书模块清单为准做一一映射，可改名不可丢功能。

```
登录
 └─ 服务器 / 代理配置（可折叠高级设置）

主界面（Home Hub）
 ├─ 入库作业     采购入库 / 生产入库 / 其他入库 …
 ├─ 出库作业     销售出库 / 领料出库 / 其他出库 …
 ├─ 库内作业     移库 / 上架 / 下架 / 调拨 …
 ├─ 盘点作业     按单盘点 / 盲盘 / 复盘 …
 ├─ 查询中心     库存 / 物料 / 单据 / 条码追溯 …
 └─ 我的         账号、仓库切换、关于、退出、环境信息
```

**主界面设计原则：**

- 一屏一构图：顶区品牌 + 当前仓库/用户，中部 **4～6 个清晰分类入口**，底部次要入口
- 分类用大触控热区（PDA 戴手套可点），图标语义明确，少字
- 不用卡片堆砌仪表盘；不做统计条抢主视觉
- 进入分类后再列具体作业，避免首页入口超过一屏滚动过多

**典型作业流（示例：扫码入库）：**

1. 选单据或建单 → 2. 扫物料/托盘条码 → 3. 确认数量/库位 → 4. 提交 → 5. 声光反馈 + 下一枪

每步单职责；扫码框常驻、自动聚焦；成功短振动 + 清晰状态色。

## 6. 登录页 UI 规范（按你的要求固化）

### 6.1 视觉

| 元素 | 规范 |
|------|------|
| 背景 | **充电器生产企业仓库**真实高清图，全屏 edge-to-edge（非圆角小图、非侧栏） |
| 遮罩 | 深色渐变遮罩（建议顶部略透、中部登录区约 55%～70% 暗度），保证白字可读 |
| 品牌 | 「辰阳电子 WMS」为英雄级品牌信号，压过副标题 |
| 登录框 | **半透明毛玻璃**：`BackdropBlur` + 半透明填充 + 细描边；圆角适中（非胶囊堆） |
| 字段 | 账号、密码；可选「记住账号」 |
| 高级设置 | 折叠面板：**服务器地址（IP/域名 + 端口）**、**代理地址（ngrok HTTPS URL）**、连接测试 |
| CTA | 单一主按钮「登录」 |
| 动效 | 背景轻微 Ken Burns 或遮罩淡入；登录框入场上移淡入；按钮 loading |

### 6.2 网络配置模型（登录页必有）

```text
生效 BaseUrl 规则（建议）：

若「代理地址」非空：
  BaseUrl = 代理地址（如 https://xxxx.ngrok-free.app）
  可选附加 ngrok 跳过浏览器警告 Header：ngrok-skip-browser-warning: true
否则：
  BaseUrl = http(s)://{服务器IP或域名}:{端口}{可选 pathPrefix}

持久化键：
  server_host / server_port / use_https / path_prefix
  proxy_url（完整，含 scheme）
  last_username / remember_flag
```

**连接测试：** 点「测试连接」打说明书中的健康检查或登录前轻量接口，展示延迟与 HTTP 状态，避免登录时才发现代理失效。

**实际与测试切换：**

- 现场：填内网 IP:端口，代理留空  
- 远程调试：填 ngrok 代理 URL，主机可灰显或仍保存便于切回  

### 6.3 资源

- 仓库背景图放入 `app/src/main/res/drawable` 或 `assets`（建议 WebP，主图 ≤ 1.5MB，提供 1x 高质量即可）
- 若需采购/拍摄：充电器产线旁的立体货架、托盘、扫码作业场景；避免抽象渐变充当主视觉

## 8. 网络层设计要点

```kotlin
// 伪代码：动态 BaseUrl
class DynamicBaseUrlInterceptor(settings: SettingsRepository) : Interceptor {
  override fun intercept(chain: Chain): Response {
    val base = settings.resolveBaseUrl() // proxy 优先
    val newUrl = chain.request().url.toHttpUrl().resolveAgainst(base)
    val req = chain.request().newBuilder().url(newUrl)
      .apply { if (settings.isNgrok()) header("ngrok-skip-browser-warning", "true") }
      .build()
    return chain.proceed(req)
  }
}
```

- 超时：连接 15s / 读 30s（可配置）；弱网提示明确
- 证书：内网 HTTP cleartext 需 `networkSecurityConfig`；ngrok HTTPS 走系统 CA
- 日志：仅 Debug 打 body；Release 脱敏

## 9. UI 主题方向（避免 AI 俗套）

- **方向**：工业仓储 · 深夜灯下作业感 —— 深蓝灰主色 + 琥珀/安全黄强调（警示/主操作），非紫白渐变、非奶油衬线风
- CSS/Compose 变量：`--bg`, `--surface-glass`, `--accent`, `--success`, `--danger`, `--text-primary`
- 字体：显示用有力量的无衬线（如 Outfit / Manrope 商用许可或思源黑体粗体中文搭配），正文清晰可读
- 动效：登录入场、主页分类交错出现、扫码成功反馈 —— 至少 2～3 处有意动效，忌到处弹跳

## 11. 验收标准

1. **功能**：说明书中的模块在新 App 均可完成同等业务闭环。  
2. **接口**：抽样 ≥ 核心接口 100% 字段兼容；同一操作新旧请求语义一致。  
3. **登录页**：全屏仓库实景 + 深色遮罩 + 毛玻璃登录框；可配 IP:端口与代理并持久化。  
4. **主界面**：分类清晰，3 秒内能找到常用作业入口。  
5. **环境**：仅改登录页配置即可在「内网直连」与「ngrok 代理」间切换，无需重打包。  
6. **体验**：扫码连续作业流畅；关键成功/失败反馈可感知。

## 12. 风险与对策

| 风险 | 对策 |
|------|------|
| 说明书接口不全 | Jadx 补全 + 旧 APK 对照抓包 |
| 无旧签名无法覆盖安装 | 新包名并行；现场卸载旧版 |
| ngrok 免费域名变更 | 登录页可改代理；配置导出/二维码分享 |
| cleartext HTTP 被拦 | `networkSecurityConfig` 按环境放开 |
| PDA 厂商键码差异 | 抽象 `ScanEvent`；可配置结束符与前缀 |
